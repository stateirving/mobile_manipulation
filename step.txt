可以从 ESDF 硬约束开始，但建议做“线性化硬约束”，不要一开始尝试把 nvblox 查询直接嵌进 CasADi/acados。你的 MPC 需要符号表达式，而 nvblox ESDF 是运行时网格/查询结果。

推荐步骤如下。

**Step 1: 固定第一版范围**
先只做静态障碍，使用离线导出的 `esdf_grid.npz`。先不要做在线 nvblox 更新。

输入来自：  
[export_nvblox_esdf.py](/home/miao/repo/mobile_manipulation/mm_run/scripts/export_nvblox_esdf.py:622)

目标是让 MPC 约束机器人 collision spheres 离 ESDF 障碍至少 `d_safe`。

**Step 2: 定义机器人 collision spheres**
把 base、arm link、end-effector 近似成若干 sphere：

```text
sphere_i:
  link/frame name
  local offset
  radius r_i
```

MPC 每个预测节点根据 `q_k` 算 sphere center：

```text
c_i(q_k) in world frame
```

第一版可以少放几个 sphere：base 1-3 个，arm 关键 link 每段 1-2 个。

**Step 3: 实现 ESDF 查询器**
读取 `esdf_grid.npz`，实现：

```python
distance, gradient, valid = esdf.query(point_world)
```

需要三线性插值：

```text
d0 = ESDF(c0)
n0 = grad_ESDF(c0)
```

对 invalid / out-of-bounds 点要保守处理，例如直接认为不安全，或者触发 fallback 停车。

**Step 4: 用上一轮预测轨迹做线性化**
对上一轮 MPC 预测 `q_bar[k]`，先在 solver 外算：

```text
c0_i,k = sphere_center_i(q_bar[k])
d0_i,k = ESDF(c0_i,k)
n0_i,k = grad_ESDF(c0_i,k)
```

然后 MPC 内不用真实 ESDF，只用一阶近似：

```text
d(c_i(q_k)) ≈ d0_i,k + n0_i,k^T (c_i(q_k) - c0_i,k)
```

**Step 5: 写硬约束公式**
对每个节点 `k`、每个 sphere `i`：

```text
d0_i,k + n0_i,k^T (c_i(q_k) - c0_i,k) - r_i >= d_safe
```

按你现有 `Constraint` 约定是 `g(x,u,p) < 0`，可以写成：

```text
g_i,k = d_safe + r_i - d0_i,k - n0_i,k^T(c_i(q_k) - c0_i,k) <= 0
```

这就是 ESDF 硬约束的核心。

**Step 6: 新增一个 ESDF constraint 类**
在 [MPCConstraints.py](/home/miao/repo/mobile_manipulation/mm_control/src/mm_control/MPCConstraints.py:121) 附近新增类似：

```text
LinearizedESDFConstraint
```

它的参数 `p` 至少包含：

```text
c0_i: 3D
n0_i: 3D
d0_i: scalar
```

每个 sphere 一组参数。`radius` 和 `d_safe` 可以写进 config，也可以作为参数。

**Step 7: 在 MPC 每次 solve 前更新参数**
在 MPC solve 前，根据当前 warm-start / 上次预测轨迹更新每个 shooting node 的 ESDF 参数：

```text
for k in horizon:
  for sphere in collision_spheres:
    q_bar = previous_prediction[k]
    c0 = sphere_center(q_bar)
    d0, n0 = esdf.query(c0)
    set_acados_param(k, c0, n0, d0)
```

这一步是关键：ESDF 查询发生在 solver 外，solver 内只看 CasADi 符号线性约束。

**Step 8: 先只加 base，再加 arm**
建议顺序：

1. base sphere 硬约束
2. end-effector sphere 硬约束
3. arm link spheres 硬约束
4. 全机器人 spheres

原因是硬约束很容易 infeasible。先少量 sphere 容易定位问题。

**Step 9: 加可行性保护**
虽然叫硬约束，工程上仍建议留保护：

```text
d_safe 先小一点，比如 0.05 m
radius 保守但不要过大
invalid ESDF 点触发 stop 或 fallback
MPC infeasible 时执行 emergency stop
```

如果一开始经常 infeasible，可以先临时开 slack 调试，确认约束方向和参数更新没错，再关掉 slack。

**Step 10: 验证**
离线先验证这些东西：

```text
ESDF slice 看起来正确
sphere center 落在正确 world frame
d0 在障碍附近变小
gradient 指向远离障碍方向
g <= 0 时确实安全
```

再跑 MPC 日志，画出：

```text
min_esdf_distance
min_constraint_margin = d_lin - r - d_safe
infeasible count
```

结论：可以从硬约束开始，但第一版最好做成“ESDF 查询外置 + MPC 内线性化硬约束”。这和你现在的 CasADi/acados 架构最匹配。
